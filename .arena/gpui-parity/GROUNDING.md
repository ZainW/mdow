# GPUI Electron-parity chrome — grounding

Read-only facts. Do not edit this file. Write your candidate only under your assigned output directory.

## Product

Mdow is a quiet markdown viewer. Electron (`apps/desktop`) is the shipping reader. GPUI (`apps/gpui`) is a native macOS beta that already renders Markdown with `pulldown-cmark` → `DocumentBlock` → GPUI elements. There is no webview in GPUI today.

The user asked for a fully working GPUI build that matches Electron, without webviews, informed by egoist/waku and longbridge/gpui-component (native TextView). Companion/AI stays out of this run.

## Done predicate

A reader-loop match, not a clone of every Electron subsystem.

In: open file/folder, tabs, live reload, sidebar modes (recents / folder / outline), find-in-document, command palette, settings (theme, content/code font, interface scale, reading width, zoom), session restore, GFM gaps Electron already shows (strike, alerts, footnotes as first-class or clearly styled), HTML documents without WKWebView, mermaid as a native card not a JS runtime, keyboard/menu parity for the reader loop.

Out: companion, editing, split view, auto-update, mermaid JS execution.

## Constraints

- GPUI crate is pinned at `0.2.2`. Official `examples/input.rs` implements a one-line `TextInput` via `EntityInputHandler`. There is no built-in Input widget.
- `apps/gpui` already has 132 passing tests and a measured visual contract (sidebar 244, reader 768, Inter 15.5/1.65, Geist Mono, Electron light/dark palette).
- Existing spec explicitly refused `gpui-component` so Mdow metrics stay authoritative. That refusal can be revisited if a candidate proves it.
- Strikethrough is currently flattened to plain text (`InlineContainer::Flatten`). Footnotes become `[^{label}]`. Math is plain text. Raw HTML is inert `RawText`.
- Electron HTML uses a sandboxed iframe. GPUI must not grow a webview.
- Persistence in Electron is `electron-store` (`recents`, `lastFolder`, `sessionTabs`, `sessionActiveTabPath`, `theme`, fonts, `interfaceScale`, `readingWidth`, `zoomLevel`, `wideMode`, `sidebarMode`).
- Electron overlays are independent booleans (`searchOpen`, `commandPaletteOpen`, `settingsOpen`, `shortcutsDialogOpen`). That is a smell. Illegal dual-open states should be unrepresentable.
- Theme currently follows `WindowAppearance` only. Electron also has system/light/dark preference.
- Wide mode is a boolean. Electron reading width is `standard | comfortable | wide`.
- Design: match Electron visual contract. Apply Emil rules that do not fight it (no layout shift, no font-weight hover, tabular nums, reduced motion, focus rings). Compact chrome stays 28–36 px. Do not invent a new marketing palette.

## Existing GPUI types

- `AppModel { tabs: TabSet, workspace: Option<WorkspaceTree>, workspace_error }`
- `MdowApp` owns model plus `sidebar_open`, `wide_mode`, drop/error/copy/link/scroll/watcher/theme/focus. Nothing persisted.
- `ParsedDocument { path, title, frontmatter_title, source, blocks, headings }`
- Actions: `OpenFile`, `OpenFolder`, `ToggleSidebar`, `CloseTab`, `ToggleWideMode`, `Quit`
